# iPAS 智慧生產工程師（初級）備考專案稽核

稽核日期：2026-09-21
範圍：教材、PWA 靜態程式與 iPAS 115 年官方簡章。未執行建置或瀏覽器測試；本次僅唯讀盤點。

## 1. 專案與執行概況

Vite 6 + TypeScript 的靜態 PWA；教材由 Markdown 經 `scripts/sync-materials.mjs` 轉入 `src/data/study-materials/`。可用指令為 `npm run dev`、`npm run sync:materials`、`npm run typecheck`、`npm run build`。目前定義 12 個考科單元及 3 個附錄。官方 115 年初級學科為科目一、科目二各 50 題、75 分鐘；科目二也可與術科三擇一報考，應將專案定位清楚標示為「兩門學科備考」。

## 2. 專案結構與職責

```text
科目一_生產與作業管理基礎/       6 份 Markdown + 單元圖
科目二_智慧製造生產線管理基礎/     6 份 Markdown + 單元圖
歷屆試題與解題技巧/               公式、陷阱、書目導引
scripts/sync-materials.mjs         Markdown 轉教材 TypeScript
src/core/                          科目、單元型別與清單
src/data/study-materials/          15 份編譯後教材
src/pages/                         首頁、單元、教材、資源、設定
src/utils/                         路由、Markdown、KaTeX、Mermaid、IndexedDB
```

## 3. 既有能力與覆蓋範圍

教材涵蓋 MRP、工時、品質、精實、ISA-95、IIoT、AI/AOI、CPS、設備與 MES，並已有公式推導、Mermaid 圖與新建的單元分解圖。PWA 具備主題與字級設定、KaTeX、Mermaid 與離線快取設定。以上是從 `src/core/topics.ts`、`TopicDetailPage.ts`、教材與 Vite 設定所作的靜態判讀，非使用者端執行驗證。

## 4. 現況差距與原因

1. **尚未形成可評量的應試閉環（最高優先）**：路由只有首頁、單元、教材、資源與設定；資料型別沒有題目／選項／正解／解析，亦未見作答頁。現有「考古題盲點」是閱讀文章，非可計分題庫。因此無法用 50 題、75 分鐘的官方學科形式驗證準備度。
2. **沒有考綱—教材—題目覆蓋矩陣**：現有 12 單元的名稱與主題完整，但缺少每項官方評鑑能力、學習頁、題目 ID、最後複核日的可追溯對照。新增或改版後容易產生無題目或無教材的盲區。
3. **題目內容缺少來源與版本治理**：附錄聲稱對應官方公告試題，但沒有題目逐題的來源、是否官方原題／改寫題、授權狀態、答案覆核者、適用簡章版本。這會使內容正確性與日後更新無法稽核。
4. **錯題複習與學習進度沒有落地**：`src/utils/db.ts` 提供 IndexedDB key-value 包裝，但主程式未初始化或使用；目前僅有主題／字級的 localStorage。沒有錯題本、熟練度、複習到期日或科目分數趨勢。
5. **分解圖尚未進入 PWA 教材管線**：圖檔放在 Markdown 教材資料夾，但 `sync-materials.mjs` 只轉換 Markdown，`TopicDetailPage.ts` 也只注入編譯後 HTML。未見圖片引用或複製到可部署資產的規則，因此目前僅能在檔案系統查看，不能保證會在 PWA 或離線快取中顯示。
6. **公式題附錄的承諾與實際不一致**：檔案宣稱「八大類」，實際標題為題型一至七；應補第八類或修正文案。另 `Ca` 以百分比呈現、`Cpk=(1-|Ca|)×Cp` 時須明確規定使用小數比例，避免讀者把 16.67 當作 16.67 而誤算。
7. **考務資訊缺乏可更新邊界**：首頁與 README 寫死題數、門檻與時程相關說明。題數／日期等易變資料應附「依據文件、版本、查核日、官方連結」，避免下一年度沿用過期資訊。

## 5. 建議優化優先序

| 優先 | 最小可行交付 | 驗收方式 |
|---|---|---|
| P0 | 題庫資料模型與每科 50 題、75 分鐘 CBT 模考 | 兩科均能計時、暫存作答、交卷、顯示逐題解析與分科成績 |
| P0 | 考綱覆蓋矩陣與內容審核台帳 | 每項能力至少有教材與題目；標示來源、版本、複核日 |
| P1 | 錯題本、標記不熟與間隔複習佇列 | 作答後自動入列；可依科目／單元篩選，重新答對才降級 |
| P1 | 讓 12 張單元圖在教材頁可見且可離線 | 每單元有圖、替代文字、行動版縮放；production build 內有資產 |
| P1 | 計算題互動練習器 | 支援 ST、EOQ/EPQ、ROP、OEE、線平衡、Cpk；每一步可檢查單位與答案 |
| P2 | 考前儀表板 | 顯示兩科近三次模考、各能力正確率、到期複習量與弱項建議 |

## 6. 建議新增內容

### 題庫與品質

- 為每個單元先建立 20–30 題原創或已獲許可的練習題，並至少包含概念辨析、情境判讀、計算與圖表判讀四類；題目數量不應被誤稱為官方題庫。
- 為每題提供：`id`、科目、能力點、難度、題幹、四選項、正解、逐項干擾解析、來源、版次、審核狀態。
- 把「115 年第一次公告題」設為獨立受控資料集；原文使用前先確認官方下載條款，若不適合嵌入，改放官方連結與自行撰寫的非逐字模擬題。

### 學習設計

- 加入「診斷測驗 → 弱項計畫 → 間隔複習 → 全真模考」四步流程；單純閱讀不足以證明可在 75 分鐘內完成 50 題。
- 每章加入 5 題微測驗、1 題混合情境題與 1 張公式／辨析卡；計算題可輸入過程，不只判最後答案。
- 在科目二增加資安與 OT/IT 邊界的最低限度辨析（例如 OPC UA 安全、MQTT 權限、感測資料品質），但須先以現行官方評鑑大綱確認其權重後才列為核心題庫。

### 內容與維護

- 新增 `content-manifest`：記錄教材、分解圖、題庫、官方簡章的版本、雜湊／更新日、審核人。
- 將分解圖納入 Markdown 或資產清單，提供描述性 alt text；不要依賴桌面絕對路徑。
- 補一份「內容勘誤與版本紀錄」，先修正公式附錄的題型數與 Ca/Cpk 表示法。

## 7. 可直接執行的五個小任務

1. **建立題庫型別與資料驗證**：新增純資料型別與 JSON/TS schema，不做 UI。驗收：每題必填來源、能力點、四選項與唯一正解；`npm run typecheck` 通過。
2. **建立考綱覆蓋矩陣**：建立一份 Markdown/JSON，列出官方能力點到單元與題目 ID。驗收：12 個單元均有條目，所有能力點可追溯。
3. **製作科目一 CBT MVP**：50 題、75 分鐘、題號跳轉、暫存答案與成績報表。驗收：離開頁面後可恢復，交卷後有題目解析。
4. **製作錯題與複習排程**：使用既有 IndexedDB helper，儲存作答紀錄與到期日。驗收：答錯題可在「今日複習」出現，答對後更新熟練度。
5. **納入分解圖與修正公式附錄**：建立可部署圖資規則，補第八題型或改為七大類，統一 Ca/Cpk 的比例表示。驗收：`npm run build` 後 12 張圖可從教材頁載入。
