# 卡牌與模擬規則

狀態：待實作的行為契約。卡牌是玩家提交的工程決策；模擬引擎根據條件產生結果，畫面只負責呈現。公式的精確定義見 [06](06_公式與易錯觀念.md)。

## 1. 卡牌定義

| 欄位 | 內容／約束 |
| --- | --- |
| id、version、family | 穩定識別、規則版本、下表卡牌家族 |
| name、description | 繁體中文名稱、用途；顯示具體效果及代價 |
| topicCodes、conceptIds | 對應章節與能力，不由名稱猜測 |
| targetType、parameters | 可選對象、數值／列舉參數、單位、範圍與必要欄位 |
| prerequisites | 資料、材料、時序、核准、狀態與適用模型條件 |
| cost | 預算、操作額度、佔用工時／資源；分開存放不同量綱 |
| effectiveAt、duration | 立即、下一時點、指定到貨日或執行期間 |
| effects | 具名操作與參數；不得載入可任意執行的程式字串 |
| stacking、uses | 不可疊加、取代政策、互斥組或有限次數 |
| evidence、feedback | 要產生的事件、觀念證據及失敗原因 |
| sourceRefs | 教材章節、規則說明、必要的模型假設 |

章節文件中的語義名稱是卡牌變體名稱；例如「EDD 排序」「SPT 排序」都是 F01 的具體卡。實作每關時須展開為完整定義，不能把文案本身當成執行邏輯。

## 2. 卡牌家族與行為

| family | 卡牌例子 | 實際改變 | 必要約束／代價 |
| --- | --- | --- | --- |
| F01 計畫 | MTS／ATO 政策、MPS 調整、EDD／SPT／CR 派工 | 庫存解耦點、工單順序、承諾量 | 產能、到料、交期與加工中不可任意中斷 |
| F02 流程文件 | 途程排序、MBOM 轉換、ECN 核准、SOP 更新 | 工序依賴、用料版本、生效批次 | 文件、工單、配方版次一致才可釋放 |
| F03 物料 | MRP 展開、L4L／EOQ／EPQ、ROP、盤點、移轉 | 到貨排程、批量、庫存位置及狀態 | 前置時間、p>d、庫存位置及單位一致 |
| F04 工作研究 | 動作刪減、工位重排、測時、寬放計算 | 動作路徑、標準工時與可分割任務 | 工序先後、技能、必要休息與作業安全 |
| F05 產線改善 | 瓶頸治具、工作移轉、並聯工站 | 指定工站服務時間、容量及前置關係 | 預算、安裝停機、工序可分割性與整線限制 |
| F06 品質分析 | PAF 分類、管制圖、能力分析、抽樣 | 分類、證據、估計與異常判斷 | 圖種／樣本／規格正確；分析不直接改善製程 |
| F07 品質處置 | 首件放行、批次隔離、原因確認、防呆 | 批次狀態、放行條件、特定錯誤機率 | 需證據與有效程序；隔離降低可交貨量 |
| F08 精實 | 5S、ECRS、看板、SMED、改善試驗 | 動作、WIP 上限、換線時間及拉動規則 | 下游需求、容器數、實際改善依據 |
| F09 維護 | 自主保養、預防保養、故障維修、備件配置 | 計畫停機、修復時間與指定失效機制 | 生效前需佔用設備；不增加理想加工速率 |
| F10 架構 | ISA-95 責任配對、主資料契約、整合方案 | 指令責任、資料欄位、交換方向 | 正確決策時間尺度、控制權限與主資料 |
| F11 資料取得 | 感測器、量程換算、時間同步、品質檢核 | 可見資料、單位、品質旗標與時間戳 | 量程與精度、取樣周期、資料新鮮度 |
| F12 通訊 | Modbus 對應、OPC UA 設定、MQTT 訂閱、邊緣緩存 | 解碼、權限、傳送路徑、待同步佇列 | 協定／資料語義適配、斷線與重送 |
| F13 AI／視覺 | 光源選擇、標註、資料切分、門檻、人工覆核 | 成像、模型評估資料、混淆矩陣與判定路徑 | 固定陽性定義、防資料洩漏、成本和漏檢約束 |
| F14 模型／控制 | 5C 配對、模型校驗、虛擬調試、閉迴路設定 | 模型參數、受控回寫與驗證狀態 | 延遲、誤差、模型適用範圍與回退方案 |
| F15 設備／搬運 | PLC 掃描、互鎖、機器人選型、AGV／AMR／ASRS | 設備狀態、任務指派、路徑及容量 | 互鎖、載重、區域佔用、復歸與授權 |
| F16 MES／追溯 | 工單釋放、掃碼、報工、Andon、8D、R2R | 工單與批次事件、升級流程、下批參數 | 版次、冪等、追溯完整性、核准與因果確認 |

此表定義十六種可重用行為，並非只有十六張卡。各章會有多個具名變體，每關可用牌組、成本和目標以關卡資料為準。

## 3. 一張完整卡牌範例

| 欄位 | 工站 B 治具改善卡 |
| --- | --- |
| id／family | fixture-b-v1／F05 |
| 初始對象 | 依序加工 A→B→C，服務時間 20、40、25 秒／件 |
| 前提 | 教學模型在正式運轉前，B 未有相同治具；本關假設已備妥治具 |
| 成本與上限 | 3 預算點、1 行動額度、最多使用一次 |
| 效果 | B 的服務時間由 40 秒改為 30 秒，A 與 C 不變 |
| 量測模式 | 穩態理論：每小時產能由 3600/40=90 改為 3600/30=120 件 |
| 不合理操作 | 資源不足／目標不是 B／重複加成，維持原狀並顯示原因 |
| 延伸情境 | 若加入安裝 10 分鐘，必須改用有限班次模擬比較淨產出，不沿用 120 件結算 |
| 學習證據 | 能指出瓶頸、預測改善方向，並辨識加工時間與需求節拍不同 |

## 4. 回合與事件順序

回合是玩家決策窗口，可代表一班、一天、一個批次或一次診斷。各關必須宣告 horizon、timeUnit 與 roundDuration；時間粒度不能由動畫幀率決定。

1. 從指定 seed 與內容版本建立初始狀態，保存不可變快照。
2. 讀入已知訂單／到貨／設備狀態，顯示本輪玩家可取得的資訊。
3. 收集預測與出牌，依序驗證前提；只有合法提交才扣成本。
4. 以模型時間處理已排定事件；同時點採關卡固定規則：安全／停機、完成作業／到貨、狀態交易、釋放新作業。
5. 記錄每次變動的前值、後值、原因及來源 actionId；防止同一動作重複扣款。
6. 重新計算 KPI，判斷約束與目標，保存本輪快照及回放紀錄。
7. 評估觀念檢核；滿足條件才更新學習進度。新一輪或重試都從明確快照開始。

班次起訖包含規則必須明訂：完成時刻等於截止時間可計入，截止後不能計入。MRP 則以離散期別宣告「期初到貨、期間需求、期末結存」。兩種時間模型不得混算。

## 5. 模型邊界與不變條件

| 模型 | 必須保存的狀態 | 必須成立的規則 |
| --- | --- | --- |
| 產線 | 各站加工／等待／阻塞／停機、緩衝區、工件身分 | 每件遵守途程，資源不能重疊佔用，產出守恆 |
| 物料 | 在庫、可用、保留、在途、隔離、需求與收發交易 | 不足料形成欠交／未滿足需求，不能靠負實體庫存繼續生產 |
| 排程 | 工單加工時間、到達時間、交期、資源 | 依所宣告的單機／多機與可搶佔條件計算績效 |
| 品質 | 真實品質、檢測判定、規格、抽樣與批次 | 檢驗改變可知資訊及處置；只有改善措施改變生成品質的機制 |
| 維護 | 故障事件、運轉時間、修復事件、計畫時間 | A/P/Q 的分母與停機分類固定，零分母回傳無法計算 |
| 通訊 | 訊息 ID、來源時間、接收時間、型別、單位與品質 | 重複訊息不得重複入帳；過期／無效資料不得偽裝為即時值 |
| AI | 固定樣本標籤、預測分數、切分集合及門檻 | 同一資料不可同時訓練與最終評估，矩陣與閾值一致 |
| 設備 | 狀態、互鎖、配方版本、授權及區域佔用 | 停機到復歸到啟動按允許轉移，不能由報表直接繞過控制 |
| MES | 工單、物料批次、序號、工序、文件、事件版本 | 保留取消／補報／沖銷歷程，跨系統對帳可重建同一製造事實 |

隨機品質或故障必須由固定 seed 決定。教學用事件也可採腳本，以保證關卡可解；挑戰用多種已驗證的 seed。玩家不能因一個不可避免的抽牌或事件失敗而被判不理解。

## 6. 關卡資料契約

| 欄位 | 必填內容 |
| --- | --- |
| id、version、chapterId | 唯一關卡編號、內容版本、章節；T/X 也有明確類型 |
| topicCodes、conceptIds、sourceRefs | 教材與核心概念的可追溯對照 |
| prerequisites、mode | 建議先修、教學／引導／挑戰模式 |
| scenario、assumptions | 任務目標、模型類型、規格、起始WIP、單位與假設 |
| initialState、seed、horizon | 可重建初始狀態及時間範圍 |
| cardPool、startingHand、rules | 可用牌、固定開手、成本與限制覆寫 |
| scriptedEvents | 觸發時機、事件資料、玩家能提前得知的資訊 |
| objectives、constraints | 每個可判定目標的運算子、閾值、單位與評估時點 |
| knowledgeChecks | 原因題／證據選擇／排序的答案規則與錯誤觀念 |
| referenceSolutions | 至少一條可重播通關路徑；判分不要求唯一出牌順序 |
| star2Objectives、transferVariants | 額外效率條件及新情境；變體沿用原 levelId |
| feedback、materialLinks | 未達成原因、計算步驟、教材與相關練習入口 |

數值關卡原則上直接比較未四捨五入的數值，顯示與作答精度另行宣告；輸入百分比與比例先明確轉換。所有超出模型適用範圍的輸入，回傳可理解的原因，不能靜默截斷製造「正確」結果。

## 7. 多個可行解與回放

目標是驗證策略能否達成任務。替代卡組若滿足同樣約束、成果及觀念證據，應通過；參考解只用於內容驗證與提示。全域最佳解只有在關卡明確定義有限搜尋空間及目標函數時才可作必要條件。

回放保存內容版本、seed、初始快照摘要、合法／被拒動作、事件與結果。比較兩方案要保留同一基準，重試不能偷換較容易的故障或需求。資料更新後若舊引擎無法回播，標記為舊版歷史結果，保留紀錄並引導重新練習。
